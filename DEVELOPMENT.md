# Сопровождение RuTracker Plus 2.7.0

Автор расширения: jnz.

## Основание переработки

Код переработан с опорой на принципы Стива Макконнелла из «Совершенного кода»,
2-е издание: управление сложностью, связность функций, ограничение зависимостей,
понятные имена, проверка внешних данных, единый стиль и проверяемое поведение.
Это инженерная интерпретация рекомендаций для JavaScript и Manifest V3,
а не утверждение о сертификации или буквальном выполнении каждой рекомендации книги.
Комментарии написаны специально для проекта; текст книги не воспроизводится.

## Принятые правила

1. Функция выполняет одну связную операцию. Например, requestJson не выбирает фильм,
   а selectExactMovie не делает сетевых запросов.
2. Отличия провайдеров сосредоточены в RATING_PROVIDERS. Интерфейс рейтинга работает
   с общей моделью, а не выдаёт поля IMDb за поля Кинопоиска.
3. Таймауты, интервалы, сроки кэша и пределы вынесены в именованные константы.
   Суффиксы Ms, Seconds и Px обозначают единицы измерения.
4. Настройки и сообщения проверяются на границе системы. Неизвестные типы сообщений
   игнорируются. Ошибочная структура API не превращается в «фильм не найден».
5. Комментарии объясняют ограничения и причины решений: кодировку XHR, защиту от
   неверного сопоставления фильмов, порядок вставки элементов, освобождение ресурсов.
6. Геометрия меток задаётся одним CSS-блоком. Контраст текста рассчитывается одной
   функцией для страницы и предпросмотра.
7. Пустой catch используется только там, где ошибка намеренно поглощается для
   продолжения очереди; ошибки пользовательских действий отображаются в интерфейсе.
8. Состояние кнопки рейтинга — idle, loading или loaded. Логика не сравнивает надписи.
9. Сброс формы меняет только settings. Ключи и пользовательские отметки сохраняются.
10. Не добавляются классы и универсальные слои, когда простых функций достаточно.

## Контракты и данные

Сохранены прежние ключи хранилища settings, kpApiKey, imdbApiKey,
rtp.mark.<topicId>.favorite, rtp.mark.<topicId>.watched и префиксы кэша.
Поэтому обновление поверх старой папки не требует повторного ввода настроек.
API-ключи отсутствуют в поставке. Веб-страница не получает их через ответы
background.js; ключи хранятся в локальном хранилище расширения, не в DOM.

Результат поиска рейтинга имеет state: matched, unmatched, disabled, no-key или error.
Только matched содержит подтверждённый ID. Сопоставление требует совпадения года и
нормализованного названия; неоднозначный результат оставляет ссылку на поиск.
Кэш КП: 24 часа для найденного фильма, 1 час для отсутствия совпадения.
Кэш IMDb: 5 минут. Очередь и защита от повторных запросов живут в service worker,
который Chrome может остановить; постоянный кэш переживает его перезапуск.

## Автоматические проверки

В распакованной папке RuTracker-Plus, где лежит package.json:

```powershell
npm install
npm test
```

Тесты не обращаются к реальным API и не расходуют квоты. Требуется современный Node.js,
совместимый с jsdom, указанным в package.json (движок указан там же).

- dom.cjs: ручная и автоматическая подгрузка, повтор после ошибки, защита от дублей,
  очистка импортируемого HTML, сортировка в обе стороны, качество и UHD.
- marks.cjs: независимость отметок, синхронизация вкладок/доменов, сохранность при сбросе.
- options.cjs: чтение, сохранение, цвета и сброс формы.
- ratings.cjs: точность выбора, кэш, дедупликация, неоднозначность, ошибки авторизации.
- rating-ui.cjs: отсутствие запросов до клика, оба провайдера, автоматический режим.
- defensive.cjs: повреждённые настройки, недоверенные отправители, неожиданный ответ API.

Проверки выполнены в Node.js и jsdom. Они не заменяют запуск расширения в Chrome.
Перед публичным выпуском нужно вручную проверить popup, разрешения, service worker,
реальные страницы списка и темы, смену цвета, клики по рейтингам и загрузку страниц.
Живая сеть провайдеров в рамках этой переработки повторно не проверялась.
